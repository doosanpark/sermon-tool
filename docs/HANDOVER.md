인수받는 개발자가 **가장 먼저** 읽을 문서. 코드를 읽기 전에 이 한 장을 읽으면

## 2. 인수 첫날 순서

1. `README.md` 의 "5분 만에 돌려보기" 대로 GUI 를 띄운다.
2. `python selftest.py` 와 `python guitest.py` 가 통과하는지 본다.
   앞은 외부 도구 없이 도는 로직 검사, 뒤는 창을 실제로 만들어 눌러 보는 검사다.
3. 예배 영상 하나로 **자동으로 찾기 → 설교 영상 만들기** 를 끝까지 해 본다.
   이걸 한 번 해 보지 않고 코드를 읽으면 용어가 안 붙는다.
4. 코드는 이 순서로 읽는다:
   `core/voiceprint.py` → `core/marker.py` → `core/export.py` → `core/cut.py` → `app.py`
5. `docs/구현문서.md` 의 "이 코드가 겪은 함정들" 을 읽는다. 같은 실수를 다시 하지 않기 위한 목록이다.
6. 3분 요약을 만질 거면 `docs/변경기록_20260831_3분요약.md` 를 읽는다.
   왜 이 모양인지와 실측 숫자가 거기 있다.

## 3. 근거 있는 숫자

추측이 아니라 실제로 재서 얻은 값이다. 바꾸기 전에 다시 재라.

**검출 정확도** — 성문 만들 때 쓰지 않은 영상 2편으로 검증

| 영상 | IoU |
|---|---|
| EH0QMvwOtm0 | 97.0% |
| Il5UP9znEzE | 97.8% |

- 설교 구간 안 유사도 0.80 / 밖 0.36~0.40 → 임계값 0.6
- 임계값을 0.55~0.65 사이 어디로 놓아도 결과가 거의 같다 (민감하지 않다)
- 6월·7월 영상으로 만든 성문이 4월 영상에서도 맞았다
- 80분 영상 스캔에 CPU 75초 (화자 분리 대비 약 60배)

**3분 요약** — 2026-07-26 설교(ZEKoljLiXOw, 설교 36.2분 / 전사 551문장)

| 잰 것 | 값 |
|---|---|
| 0.8초 이상 쉼 | 296곳 (평균 7초에 한 번) |
| 2초 이상 문단급 쉼 | 86곳 (평균 25초에 한 번) |
| **전사문 문장 사이 간격** | **550건 전부 0.000초** — 쉼 정보가 아예 없다 |
| 문장 시작 → 가장 가까운 실제 쉼 | 중앙값 1.98초 · 최대 49초 |
| 요약 결과 | 조각 15개 · 2분 55초 · 압축비 11.8:1 |
| 1차 선정이 목표를 넘긴 정도 | ＋23% (221.6초 / 목표 180초) |
| 스냅이 구간을 벌리는 정도 | ＋19% (177초 → 210초) |
| 규칙이 고른 것 ↔ 사람이 고른 것 겹침 | 19% — 규칙만으로는 부족하다는 근거 |
| 36분치 쉼 찾기 | 0.7초 (불러올 때마다 해도 된다) |
| 설교 35분 자막 만들기 | 20~60분 (CPU) — 진행 표시가 반드시 있어야 한다 |

**소리** — 예배 방송 40초 구간 실측

| | 잡음 바닥 |
|---|---|
| 원본 | −59.2 dB |
| 약하게 `highpass=80,afftdn=nf=-25` | −72.2 dB |
| 강하게 `highpass=80,afftdn=nf=-35:nr=20` | −78.3 dB |
| RNN 방식 `arnndn` | −60.2 dB → **채택 안 함** |

`arnndn` 은 잡음 종류가 사람 말소리와 겹칠 때 강한데, 이 방송의 문제는
웅웅거리는 정상(定常) 잡음이라 FFT 방식이 맞았다.

음량은 `loudnorm=I=-16:TP=-1.5:LRA=11`. 원본 −48.1 LUFS 짜리를 −16.0 LUFS 로
끌어올리는 것을 확인했다.

**확인된 예배 구조** (검출 규칙의 근거)

```
… → 설교 33~39분 → 찬양·헌금 3~4분 (목사님 아님) → 축도 2.8~3.9분 → 끝
     시작은 늘 31~38분 지점
```

## 4. 되돌리면 안 되는 결정

바꾸고 싶어지는 순간이 오는데, 이유가 있어서 이렇게 되어 있다.

| 결정 | 이유 |
|---|---|
| **화자 분리(pyannote) 대신 성문** | CPU 전용 PC에 설치해야 한다. torch 를 넣으면 설치본이 2GB 넘게 늘고, 80분 영상에 30~90분 걸린다 |
| **런타임에 torch 없음** | 위와 같다. `requirements.txt` 의 torch 계열은 주석 처리되어 있다 |
| **마우스만으로 전부 가능** | 쓰는 사람이 컴퓨터를 잘 모른다. 단축키는 보조 |
| **설교자는 "목사님"** | 교회 문서·화면 전부. 코드 식별자만 `pastor` |
| **빠른 컷이 기본, 정확한 컷은 선택** | 설교 시작·끝은 앞뒤 여유가 있어 몇 초 밀려도 무해한데, 재인코딩은 40분 분량에 20~30분 걸린다 |
| **자막 선택지는 "끌 수 있나/없나" 한 축** | 예전에 "파일로만/영상에 넣기/태우기" 셋이었는데 앞 둘의 차이를 사용자에게 설명할 수 없었다 |
| **`bin/` 에 실행파일 동봉** | 교회 PC 에서 ffmpeg 설치를 시킬 수 없다 |
| **요약 편집은 자막에서 문장 켜고 끄기** | 타임라인 막대로 되돌리면 안 된다. 교회용 클립 도구들이 공통으로 도달한 결론이고, 초 단위를 다루게 하는 순간 쓰시는 분들이 손을 못 댄다 |
| **요약은 `summary_picks`, 설교는 `clips`** | 섞으면 [설교 영상 만들기] 가 요약 조각을 이어붙인 영상을 뱉는다 |
| **요약 길이는 `highlight.runs(marks, snap)` 한 곳에서만** | 스냅이 구간을 ＋19% 벌린다. 두 곳에서 세면 화면이 거짓말을 한다 |
| **세로는 크롭이 아니라 짜맞추기** | 9:16 으로 자르면 폭이 405px 만 남아 설교 제목 화면이 날아간다 |
| **llama.cpp 는 `cpu-x64` 판만** | CPU 세대별 DLL 14개가 실행 중에 골라 불려 어떤 윈도우 PC 에서도 돈다. CUDA 판은 "CUDA 없는 PC" 원칙에 어긋난다 |
| **임베딩·AI 는 없어도 돌아야 한다** | 켜서 나빠지는 일은 없어야 한다. `selftest.check_stages()` 가 지킨다 |

## 5. 목사님이 바뀌면 (운영 절차)

성문은 사람마다 다르므로 다시 만들어야 한다. 30분이면 된다.

```powershell
# 1) 새 목사님 설교 영상 2~3편을 GUI 로 잘라 data/export 에 모은다
#    (설교 구간만 들어 있어야 한다. 축도·찬양이 섞이면 성문이 흐려진다)

# 2) 성문 만들기
python enroll.py build

# 3) 검증 — 반드시 성문에 쓰지 않은 영상으로
python enroll.py test <영상URL 또는 파일>
```

IoU 가 90% 아래로 나오면 영상을 더 넣거나, 잘라 모은 구간에 다른 사람 목소리가
섞였는지 본다. `enroll.py` 는 유사도 하위 20% 구간을 버리고 다시 평균 내므로
약간의 오염은 스스로 걸러낸다.

## 6. 깨질 수 있는 것들 (알려진 위험)

| 위험 | 징후 | 대처 |
|---|---|---|
| **유튜브가 다운로드 방식을 바꾼다** | "영상 가져오기" 실패, yt-dlp 오류 | `bin/yt-dlp.exe` 를 최신판으로 교체. 가장 자주 생길 일이다 |
| **deno 없이는 포맷을 못 읽는다** | 위와 같은 증상 | `bin/deno.exe` 가 있는지 확인. yt-dlp 가 유튜브 JS 를 풀 때 쓴다 |
| **exe 에 서명이 없다** | 윈도우 SmartScreen 경고 | 지금은 "추가 정보 → 실행"으로 넘긴다. 코드 서명 인증서를 사면 없어진다 |
| **자막 태우기 글꼴** | 다른 PC 에서 자막이 네모로 깨짐 | 윈도우 기본 `Malgun Gothic` 을 쓴다. 없는 환경이면 `cfg.subtitle_font` 변경 |
| **성문 모델 파일 누락** | [자동으로 찾기] 가 비활성 | `bin/models/campplus.onnx` (27MB) 가 있어야 한다 |
| **rc 판 파이썬으로 빌드** | PyInstaller `IndexError` | `build_all.bat` 이 정식판을 찾아 쓴다. 우회하지 말 것 |
| **HuggingFace 토큰** | 화자 분리 폴백만 해당 | 평소 경로에는 필요 없다. 폴백을 쓸 때만 `.hf_token` |

## 7. 남은 일 (우선순위 순)

1. **임베딩·AI 모델 품질 확인** — `python setup_ai.py` 로 진짜 모델을 받아
   규칙 / ＋임베딩 / ＋AI 를 견준다. 배관은 검증됐지만 품질은 아직 모른다.
   이걸 해야 `use_llm` 을 기본으로 켤지 정할 수 있다.
2. **설교 3~4편 더 확보** — 3분 요약의 뼈대는 목사님이 "첫 번째에요" 처럼 번호로
   선언하시는 것에 기댄다. 영상 한 편으로만 확인했다. 매주 그런 구조가 아니면
   AI 가 할 일이 훨씬 많아진다.
3. **완료 알림** — 지금은 로그를 봐야 끝난 걸 안다. 40분짜리 작업이라 알림이 실질적으로 유용하다.
4. **`auto.py` 실전 검증** — 코드는 있으나 몇 주 돌려본 적이 없다. 실패 시 재시도·중복 처리를 봐야 한다.
5. **배치 탭** — 폴더에 든 영상을 한꺼번에.
6. **자막 위치·크기 GUI 노출** — 지금은 `cfg.subtitle_font` / `subtitle_size` 로만 바뀐다.
7. **라이브 실시간 검출** — 성문 방식이라 CPU 로 충분히 가능하다(실시간의 100배 여유).
   스트림 녹화와 재접속 처리가 남았다.
8. **학습 모델** — 라벨이 30~50편 쌓인 뒤에나 의미가 있다. `core/detect.py` 의 인터페이스를
   고정해 두었으므로 그 파일만 갈아 끼우면 된다. 마커에 `ai_*` 와 `human_*` 을 함께 남기는 것도
   이걸 위해서다.

## 10. 정리하다 남긴 것

- `data/_to_delete/_subtest/` — 자막 기능 시험용 임시 폴더. 지워도 된다.
- `check_speakers.py` — 화자 분리 시절 전제 검증 스크립트. 지금 경로에서는 안 쓰지만,

  (실측치는 3장에 있다).
