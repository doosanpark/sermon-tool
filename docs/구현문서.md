## 1. 무엇을 푸는가

유튜브에 올라오는 1~2시간짜리 예배 영상에서 **설교와 축도 구간만** 뽑아
하나의 영상으로 만든다. 주 1회 반복 작업이며, 완전 자동이 아니라
**"AI 제안 → 사람이 30초 확인 → 내보내기"** 를 전제로 한다.

### 확인된 예배 구조

실제 영상 6편에서 확인한 구조다. 이 구조가 모든 판정의 근거다.

```
찬양·기도·봉독 → 설교 33~39분 → 찬양·헌금 3~4분 → 축도 2.8~3.9분 → 끝
                 (31~38분 지점에서 시작)   (목사님 아님)
```

| 영상 | 설교 | 길이 |
|---|---|---|
| `-LcoG7a-9QY` | 38:00 ~ 1:11:47 | 33.8분 |
| `EH0QMvwOtm0` | 31:34 ~ 1:10:23 | 38.8분 |
| `EePRm6IoHaU` | 37:13 ~ 1:14:42 | 37.5분 |
| `_uOmx9IPzfY` | 34:58 ~ 1:08:14 | 33.3분 |
| `eTsS87MhO1A` | 36:39 ~ 1:10:03 | 33.4분 |

**축도는 설교 직후가 아니다.** 중간에 찬양·헌금이 3~4분 들어간다.
이 공백이 축도를 찾는 핵심 단서다.

## 2. 검출 방식 — 왜 성문인가

### 처음 설계(화자 분리)와 무엇이 달랐나

명세 v2 는 pyannote 화자 분리로 "가장 오래 말한 사람 = 목사님" 을 찾는 방식이었다.
동작은 했지만 **CPU 에서 80분 영상당 30~90분**이 걸렸고, torch·pyannote 로
설치본이 3~6GB 가 되어 배포가 불가능했다. HuggingFace 토큰과 게이트 저장소
3곳 승인도 필요했다.

### 지금 방식(성문 대조)

목사님 목소리를 **미리 한 번** 등록해 두고, 런타임에는
"지금 3초가 목사님 목소리인가" 만 판단한다.

```
[한 번]  이미 잘라 둔 설교 영상 3편 → 3초 창마다 임베딩 → 평균 → voiceprint.npz (2KB)

[매번]   전체 오디오를 3초 창으로 훑기 → 성문과 코사인 유사도
         → 임계값 0.6 → 블록 병합 → 최장 블록 = 설교
                                  → 그 뒤 공백 지나 오는 블록 = 축도
```

| | 화자 분리 | 성문 대조 |
|---|---|---|
| 80분 영상 | 30~90분 | **75초** |
| 의존성 | torch + pyannote (2GB+) | ONNX 28MB |
| 토큰 | HuggingFace 필요 | 불필요 |
| 설치본 | 3~6GB | 600MB |

**모델**: `3dspeaker_speech_campplus_sv_zh_en_16k-common_advanced.onnx` (CAM++, 192차원)
sherpa-onnx 로 실행. 3초 창 임베딩 1회에 CPU 0.023초.

### 실측 정확도

성문 제작에 **쓰지 않은** 영상으로 검증했다.

| 영상 | 정답 | 검출 | 시작 오차 | 끝 오차 | IoU |
|---|---|---|---|---|---|
| `EH0QMvwOtm0` | 31:34 ~ 1:10:23 | 31:42 ~ 1:11:27 | +8초 | +64초 | **97.0%** |
| `Il5UP9znEzE` | 37:37 ~ 1:13:43 | 38:15 ~ 1:13:33 | +38초 | −10초 | **97.8%** |

축도도 함께 검출된다 (오차 +3초/−33초, −3초/0초).

유사도 분리:

```
설교 구간 안  0.80 ~ 0.81
설교 구간 밖  0.36 ~ 0.40
```

임계값을 0.55~0.65 어디에 둬도 결과가 같다. 경계에 민감하지 않다.

6~7월 영상으로 만든 성문이 **4월 영상에도 그대로 통했다.** 몇 달 차이는 문제없다.

### 데이터 흐름

```
유튜브 URL ─┐
로컬 파일 ──┴→ 오디오 16kHz 모노 ─→ 성문 대조 ─→ ServiceResult
                                                  ↓
                                    Marker(clips=[설교])  ※ 축도는 선택
                                                  ↓
                                  사람이 GUI 에서 확인·수정
                                                  ↓
                        ┌─────────────────────────┴──────────────┐
                        ↓                                        ↓
        cut(trim+concat, 잡음·음량)                    extract_mp3(소리만)
                        ↓
              prepend_intro(시작 영상)      ← 있을 때만. 자막을 밀 초를 돌려준다
                        ↓
              build_srt(lead=시작영상 길이)
                        ↓
        embed_subtitles / burn_subtitles → mp4 (+ 자막백업/*.srt)
```

**순서가 중요하다.** 시작 영상을 자막보다 먼저 붙여야 자막 시각을 그만큼 밀 수 있다.
잡음 제거는 음량 맞추기보다 먼저다 (안 그러면 잡음까지 커진다).

### Marker (`core/marker.py`)

AI 예측(`*_ai_*`)과 사람 수정본(`*_human_*`)을 **둘 다** 남긴다.
나중에 학습 데이터로 쓰기 위한 것이므로 필드를 함부로 바꾸지 않는다.

`clips` 는 실제로 내보낼 구간 목록이다. 비어 있으면 설교·축도에서 만들어 채운다.
사람이 GUI 에서 편집하면 `clips` 만 바뀐다. `*_ai_*` 는 보존되므로
**[AI가 찾은 구간으로]** 로 언제든 되돌릴 수 있다.

## 4. 핵심 알고리즘

### 성문 등록 (`voiceprint.enroll`)

1. 이미 잘라 둔 설교 영상에서 3초 창을 뜬다 (무음 제외, RMS ≥ 0.01)
2. 각 창의 임베딩을 구해 평균 → 1차 성문
3. 1차 성문과의 유사도가 하위 20% 인 표본을 버리고 다시 평균 → 최종 성문

3단계가 있어야 설교 중 섞인 다른 소리(반주, 회중 반응)가 성문을 흐리지 않는다.
실제로 표본 373개 중 298개만 남았다.

### 구간 판정 (`voiceprint.find_service`)

```python
blocks = 유사도 ≥ 0.6 인 창을 45초 이하 간격이면 병합
sermon = 가장 긴 블록
축도  = sermon 이후 블록 중
        · 길이 1~8분
        · 앞 공백 ≥ 60초
        조건을 만족하는 것들 중 가장 뒤엣것
```

신뢰도 = 0.4×(성문 대비/0.35) + 0.4×(길이 정상) + 0.2×(최장/2위 비율/4)

`auto.py` 는 신뢰도 0.9 이상일 때만 자동으로 자른다. 그 아래는 `review` 로 남긴다.

### 잡음 제거와 음량 맞추기

순서가 중요하다. **잡음 제거 → 음량 맞추기.** 반대로 하면 잡음까지 증폭된다.

실측(예배 방송 40초, 원본 잡음 바닥 −59.2 dB):

| 설정 | 필터 | 잡음 바닥 |
|---|---|---|
| light (기본) | `highpass=f=80,afftdn=nf=-25` | **−72.2 dB** |
| strong | `highpass=f=80,afftdn=nf=-35:nr=20` | −78.3 dB |
| (참고) RNN | `arnndn=m=cb.rnnn` | −60.2 dB |

RNN(arnndn)은 이 오디오에서 거의 듣지 않았다. 사람 말소리에 섞인 배경 소음에는
강하지만, 이 방송의 문제는 웅웅거리는 정상 잡음이라 FFT 방식이 맞다.
`bin/models/cb.rnnn` 을 받아 두었으나 쓰지 않는다.

### 음량 맞추기

실측: 이 교회 방송 원본은 평균 −40.5 dB, 최대 −18.0 dB 로 아주 작다.
(일반 유튜브 영상은 −25 dB 안팎) 잘라 낸 결과물도 같은 크기이므로,
`loudnorm=I=-16:TP=-1.5:LRA=11` 로 방송 표준에 맞춘다.

| | 평균 | 최대 |
|---|---|---|
| 전 | −40.7 dB | −18.0 dB |
| 후 | −20.6 dB | −1.4 dB |

빠른 컷 경로에서는 자른 뒤 `normalize_in_place()` 로 **영상은 복사하고 소리만**
다시 인코딩한다. 90초 분량에 2초, 40분이면 1분 안쪽이다.
정확 컷 경로에서는 filter_complex 그래프 끝에 loudnorm 을 붙인다.

### 자르기 (`core/cut.py`)

| 방식 | 명령 | 특징 |
|---|---|---|
| 정확 | `filter_complex` 로 trim+concat 한 번에 | 지정한 시각 그대로. 재인코딩이라 느림 |
| 빠름 | 구간별 `-c copy` 후 concat demuxer | 수 초. 컷 지점이 키프레임으로 밀림 |

10초 미만 구간이 있으면 빠른 방식이 빈 파일을 만들므로 **자동으로 정확 방식으로 전환**한다.

### 자막 타임라인

원본 절대시간 자막을 이어붙인 타임라인으로 옮긴다.
두 번째 구간의 자막은 첫 구간 길이만큼 밀린다 (`export.build_srt`).

### 자막을 영상에 넣는 두 방식

`cfg.subtitle_mode` 로 고른다. `export._apply_subtitles()` 가 SRT 를 쓴 직후
호출되며, 로컬 컷 경로(`export_local`)와 유튜브 구간 다운로드 경로(`export`)
양쪽에서 모두 돈다.

| mode | 방법 | 비용 | 끄고 켜기 |
|---|---|---|---|
| `embed` (기본) | `-c copy -c:s mov_text` 로 자막 트랙만 얹는다 | 40분 분량 몇 초 | 가능 |
| `burn` | libass `subtitles=` 필터로 화면에 그린다 | 전체 재인코딩 | 불가 |
| `file` | .srt 만 남긴다. **GUI 에는 노출하지 않는다** | 0 | 재생기가 불러야 함 |

`file` 은 처음엔 GUI 선택지였으나 뺐다. 사용자 눈에는 `file` 과 `embed` 가 둘 다
"자막을 껐다 켤 수 있는 것"이라 차이를 설명할 수 없었다. `embed` 가 몇 초밖에
안 걸리고 파일도 하나로 끝나므로 `file` 이 남을 이유가 없다. CLI·자동화용으로만
코드에 남겨 두었다. **선택지는 "끌 수 있나 없나" 한 축으로만 갈린다.**

`embed` 는 화면·소리를 건드리지 않고 컨테이너만 다시 쓴다. mp4 의 자막 코덱은
`mov_text` 여야 한다 — `srt` 코덱을 그대로 넣으면 mp4 muxer 가 거부한다.
`language=kor` / `title=한국어` 메타데이터를 붙여 재생기 자막 메뉴에 한글로 뜨게 한다.

`embed` 든 `burn` 이든 끝나면 `_stash_srt()` 가 .srt 를 `자막백업/` 하위 폴더로
옮긴다. 같은 이름의 .srt 가 영상 옆에 남아 있으면 VLC·팟플레이어가 자동으로
같이 읽어, `embed` 는 자막 트랙이 두 개로 보이고 `burn` 은 **태운 자막 위에
.srt 자막이 한 번 더 겹쳐 그려진다.** 지우지는 않는다 — 유튜브 업로드용으로 쓴다.

`burn` 의 스타일은 `force_style` 로 준다:

```
FontName=Malgun Gothic,FontSize=22,PrimaryColour=&H00FFFFFF,
OutlineColour=&H90000000,BorderStyle=3,Outline=1,Shadow=0,MarginV=28,Alignment=2
```

`BorderStyle=3` 은 글자 뒤에 반투명 검은 띠를 깐다. 예배 영상은 강대상 조명이
밝아 흰 글씨만으로는 묻히기 때문에 외곽선(`BorderStyle=1`)보다 띠가 안전하다.
윈도우 기본 한글 글꼴이 `Malgun Gothic` 이라 이것을 기본값으로 둔다.

**함정:** `subtitles=` 필터의 인자는 `:` 와 `\` 를 필터 문법으로 해석하므로
`D:\homily\...` 같은 윈도우 절대경로를 그대로 넣으면 깨진다. 이스케이프로
푸는 대신 **작업 폴더를 영상이 있는 곳으로 옮기고 파일 이름만 넘긴다**
(`run_stream(..., cwd=video.parent)`). 이 때문에 `util.run_stream()` 에
`cwd` 인자를 추가했다.

둘 다 임시 파일(`*.sub.mp4` / `*.burn.mp4`)로 만든 뒤 원본을 지우고 이름을
바꾼다. 같은 파일에 덮어쓰면 ffmpeg 이 입력을 읽는 중에 출력이 겹쳐 깨진다.

### 고급 설정 기억

자막 넣는 방법·잡음 제거·소리 크기는 `QSettings("창의진교회", "SermonTool")` 에
저장해 다음 실행 때 되살린다. 매주 같은 작업을 반복하는 사용자가 켤 때마다
같은 설정을 다시 고르지 않게 하기 위해서다. 콤보의 **표시 문자열이 아니라
내부 값**(`embed`/`burn`)을 저장한다 — 라벨을 바꿔도 설정이 깨지지 않는다.

### 축도는 구간 목록이 정한다

기본은 설교만이다. [축도도 함께 넣기] 는 `marker.clips` 에 축도 구간을
넣고 빼며, 내보내기는 언제나 `marker.ranges()`(= clips)를 따른다.
**보이는 목록이 곧 결과**라 설명할 것이 없다.

검출 단계의 `cfg.include_benediction` 은 GUI 에서 **항상 True** 로 둔다.
체크박스에 연동하면 축도를 아예 찾지 않게 되어, 나중에 체크를 켜도
`bene_range()` 가 비어 "축도를 찾지 못했습니다" 가 뜬다.

### 설교 mp3

`cut.extract_mp3()` — `atrim` + `concat=v=0:a=1` 로 소리만 이어붙이고
`audio_chain()`(잡음 제거 → 음량)을 그대로 태운 뒤 libmp3lame 으로 뽑는다.
말소리뿐이라 **모노 96kbps** 로 충분하다 (40분 ≈ 28MB). 설교 제목을 ID3
`title` 로 넣어 휴대폰 음악 앱에서 제목이 보이게 한다. 화면을 건드리지
않으므로 40분 분량이 1분 안쪽이다.

### 3분 요약 (`pauses` · `highlight` · `shorts`)

36분 설교에서 핵심만 골라 3분 세로 영상·mp3 로 만든다.
근거와 실측 숫자는 `docs/변경기록_20260831_3분요약.md` 에 따로 있다.
여기서는 코드가 왜 이 모양인지만 남긴다.

**전사문에는 쉼이 없다.** `faster-whisper` 를 `vad_filter=True` 로 돌리면 무음이
잘려 나가고 말만 이어 붙는다. 실측: 설교 551문장 사이 간격 550건이 **전부 0.000초**.
그래서 자를 자리는 `pauses.find_pauses()` 가 오디오에서 따로 찾는다.
50ms 프레임 RMS 를 재서 배경 소음 바닥 + 8dB 아래를 무음으로 본다.
판정선을 절대값이 아니라 **그 영상의 바닥에서 띄워** 잡는 이유는, 교회마다
마이크 험이 달라 고정값으로는 어떤 영상에서 쉼이 하나도 안 잡히기 때문이다.

**컷은 시작을 앞으로 당기고 끝을 뒤로 민다**(`snap_start` / `snap_end`).
가장 가까운 쉼에 붙이면 뒤쪽이 더 가까울 때 첫 마디가 통째로 잘린다 —
시험판에서 "두 번째입니다" 가 1초 차이로 날아갔다.

**길이는 반드시 `highlight.runs(marks, snap)` 한 곳으로만 센다.** 스냅이 구간을
앞뒤로 벌리므로(실측 177초 → 210초, ＋19%) 화면과 내보내기가 다른 방법으로 세면
"3분" 이라 떠 놓고 3분 30초짜리가 나온다. 실제로 그 버그가 있었다.

**문장 고르기는 세 단계이고, 각 단계는 없어도 된다.**

| 단계 | 함수 | 없으면 |
|---|---|---|
| 규칙 | `classify` `find_outline` `score_marks` | — (항상 돈다) |
| 임베딩 | `apply_embedding` | 규칙 결과가 그대로 |
| AI | `llm_revise` | 앞 단계 결과가 그대로 |

`make_helpers(cfg)` 가 설정을 보고 도우미를 만들어 준다. `onnxruntime` 과
`llama-server` 는 **여기서만 늦게 불러온다** — 그래야 `highlight` 자체는 그것들
없이 import 되고 `selftest` 가 가볍게 돈다.

**LLM 에게 551문장을 다 주지 않는다.** 점수 상위 90개만 넘겨 1.5만 → 3천 토큰으로
줄인다. 대목 선언은 점수와 무관하게 후보에 넣는다 — 뼈대가 후보에 없으면 LLM 도
살릴 수 없다. 답은 문장 번호 정수뿐이라 범위를 벗어나면 버리면 된다.

**세로 화면은 잘라내기가 아니라 짜맞추기다.** 9:16 으로 가운데를 자르면 폭이
405픽셀만 남아 설교 제목 화면과 십자가가 날아간다. 목사님만 크게 잡고 제목은
`marker.sermon_title` 의 글자로 얹는다. 크롭은 **비율**로 잡아(`shorts_center_x/y`,
`shorts_zoom`) 원본이 720p 든 1080p 든 같은 구도가 나오게 한다.

**자막은 ASS 로 만든다**(`shorts.srt_to_ass`). `.srt` 를 그냥 주면 libass 가
`PlayResY` 를 288 로 가정하고 영상 높이에 맞춰 6.7배로 늘린다 — 글자가 350픽셀이
되고 자막이 화면 위로 튀어 올라간다.

**요약 선택은 `marker.summary_picks` 에 둔다.** `clips` 에 넣으면 `ranges()` 가
그걸 돌려주고 `export` 가 그걸로 설교 영상을 만들어, [설교 영상 만들기] 가
조각 열댓 개를 이어붙인 영상을 뱉는다. 인덱스가 아니라 **시각**으로 적는 이유는
자막을 다시 만들면 문장이 나뉘는 자리가 달라지기 때문이다.

### 시작 영상 붙이기

`cut.prepend_intro()`. 규격이 다른 두 영상은 concat 으로 이어붙일 수 없다.
그래서 `video_params()` 로 본 영상의 해상도·fps·샘플레이트·채널을 읽고,
`_match_format()` 이 시작 영상만 그 규격으로 다시 만든다
(`scale=...:force_original_aspect_ratio=decrease` + `pad` 로 비율을 지키고
남는 자리는 검게, `setsar=1` 로 픽셀 비율까지 맞춘다). 소리가 없는 시작
영상에는 `anullsrc` 로 무음 트랙을 넣는다 — 없으면 이어붙인 뒤 소리가 밀린다.

그다음 concat demuxer + `-c copy`. **본 영상은 다시 인코딩하지 않는다.**
40분 분량이라도 몇 초다. 규격이 어긋나 copy 가 실패하면 재인코딩으로 폴백한다.

자막은 붙인 길이만큼 밀어야 하므로 `prepend_intro()` 가 돌려준 초를
`build_srt(..., lead=)` 로 넘긴다. 그래서 **시작 영상은 자막을 넣기 전에**
붙인다. 순서가 바뀌면 자막이 시작 영상 길이만큼 앞당겨진다.

### 진행률이 두 번째 파일에서 멈춰 보이는 문제 (함정)

`run_stream()` 은 진행률이 `pct_step` 만큼 올라갔을 때만 한 줄을 흘린다.
그런데 유튜브 다운로드는 **화면 → 소리 → 합치기** 3단계이고, 화면이 100%
로 끝난 뒤 소리가 0% 부터 다시 시작한다. `last_pct` 가 100 인 채라
`pct - last_pct` 가 계속 음수여서 **소리 받는 내내 한 줄도 안 나왔다.**
640MB 영상에서 몇 분간 로그가 멈춰 보였다.

세 가지로 막는다.

1. `Destination:` `[Merger]` `[dashsegments]` 같은 **새 단계 표시**가 보이면
   `last_pct` 를 초기화한다.
2. 진행률이 5% 넘게 **뒷걸음치면** 새 파일로 보고 초기화한다.
3. 15초 넘게 아무것도 못 흘렸으면 조건을 무시하고 한 줄 흘린다
   (`QUIET_LIMIT`). 어떤 이유로든 화면이 굳어 보이지 않게 하는 안전장치다.

합치는 단계는 yt-dlp 가 진행률을 주지 않으므로, 받기 전에 "합치는 동안은
진행률이 나오지 않습니다" 라고 미리 알려 준다.

### 고급 설정을 읽어 들이는 순서 (함정)

`_load_prefs()` 는 QSettings 값을 **먼저 전부 읽은 뒤에** 위젯에 넣는다.
하나씩 읽으면서 바로 넣으면, 위젯이 바뀌며 `toggled` → `_save_prefs()` 가
불려 **아직 읽지 않은 값을 현재(빈) 값으로 덮어쓴다.** 실제로 축도 체크박스를
복원하는 순간 시작 영상 경로가 지워졌다. 값을 다 읽고 → `blockSignals` 로
막고 → 넣고 → 그다음에 시그널을 연결한다.

### 자막 편집

`burn` 은 되돌릴 수 없으므로 태우기 전에 고칠 길이 있어야 한다. [자막] 탭의
줄을 두 번 클릭하면 그 자리에서 편집된다 (`QListWidget` `DoubleClicked` 트리거
+ `ItemIsEditable`). 커밋 시 `_on_subtitle_edited()` 가:

1. `[HH:MM:SS] ` 프리픽스를 정규식으로 벗겨 본문만 취한다 — 사용자가
   프리픽스를 지우거나 망가뜨려도 시간은 `UserRole` 에 있으므로 복원된다.
2. `self.transcript[idx]["text"]` 를 바꾸고 `cache/{id}.transcript.json` 에
   즉시 저장한다 — 다음에 불러와도 고친 자막이 유지된다.
3. 표시를 표준형으로 되돌려 쓴다. 이때 `blockSignals` 로 `itemChanged`
   재귀를 막는다. 목록을 채울 때도 같은 이유로 시그널을 막아야 한다.

빈 입력은 무시하고 마지막 글을 유지한다. `.srt` 는 내보내기 시점에
`self.transcript` 에서 다시 만들어지므로 편집이 그대로 반영된다.

## 5. 이 코드가 겪은 함정들

같은 실수를 반복하지 않도록 남긴다.

| 증상 | 원인 | 대응 |
|---|---|---|
| `Requested format is not available` | yt-dlp 가 JS 런타임(deno)을 못 찾음 | `bin/deno.exe` 를 PATH 앞에 붙임 (`util.tool_env`) |
| `libtorchcodec` 로드 실패 | pyannote 4.x 가 FFmpeg 공유 DLL 요구 | wav 를 직접 읽어 텐서로 넘김 |
| `DiarizeOutput has no itertracks` | pyannote 4.x 반환 타입 변경 | `_to_annotation()` 으로 버전 흡수 |
| PyInstaller `IndexError` | `--collect-all yt_dlp` / `PySide6` | collect-all 을 쓰지 않고 기본 훅에 맡김 |
| exit code 4294967274 | 오디오 트랙 없는 mp4 | `has_audio()` 로 미리 검사 |
| 구간이 3.6초로 뭉개짐 | 좁은 구간을 타임라인에서 실수로 드래그 | 24픽셀 미만이면 드래그 금지 + `Ctrl+Z` + AI 값 복원 |
| 진행이 멈춘 것처럼 보임 | yt-dlp·ffmpeg 이 `\r` 로 진행률 출력 | 한 글자씩 읽어 `\r` 도 줄바꿈 취급 (`util.run_stream`) |
| 새 영상을 열어도 앞 영상 이름으로 저장 | 마커를 비우지 않음 | `_switch_target()` 으로 대상이 바뀌면 초기화 |
| PC 마다 화면 색이 다름 | Qt 가 윈도우 다크 모드를 따라감 | Fusion + 밝은 팔레트로 고정 (`apply_light_theme`) |
| **어떤 조합으로도 PyInstaller 가 IndexError** | **파이썬이 3.10.0rc1(출시 후보)** | **정식판에서 빌드. `build_exe.check_python()` 이 미리 막는다** |
| **[정확히 자르기] 를 켜면 소리가 원본 그대로** | `cut_reencode()` 가 잡음·음량 인자를 받고도 쓰지 않음 | filter_complex 안에서 `audio_chain()` 을 태운다. 실측 −48.1 → −16.0 LUFS 로 확인 |
| 두 번째 파일 받는 동안 로그가 멈춘 듯 | 진행률이 100%→0% 로 떨어지면 억제 조건에 걸림 | 새 단계 표시에서 초기화 + 15초 침묵 시 강제 출력 (`util.run_stream`) |
| 설정을 되살리면 시작 영상 경로가 사라짐 | 복원 중 위젯 시그널이 돌아 `_save_prefs()` 가 먼저 저장 | 값을 전부 읽은 뒤 `blockSignals` 로 막고 넣는다 |
| **불러오면 요약 길이가 33초 짧게 뜸** | 불러올 때 쉼을 안 찾아 스냅 몫을 빼고 셈 | 길이는 `highlight.runs(marks, snap)` 한 곳으로만. 불러올 때도 쉼을 찾는다(0.7초) |
| **작업 중 만진 편집이 사라짐** | `_set_busy` 가 버튼만 잠그고 막대·목록은 안 잠금 | 작업이 끝나면 `_apply_marker` 가 구간을 새로 넣는다. 막대·목록까지 잠근다 |
| 세로 영상 자막이 화면 위에 거대하게 뜸 | libass 가 `.srt` 의 `PlayResY` 를 288 로 가정해 6.7배 확대 | ASS 로 만들어 `PlayResX/Y` 를 실제 크기로 적는다 |
| 자막 만들기가 멈춘 것처럼 보임 | 35분을 한 번에 넘기고 20~60분간 아무것도 안 찍음 | faster-whisper 제너레이터를 받는 족족 진행률을 찍는다 |
| 컷 첫 마디가 잘림 | 가장 가까운 쉼에 붙이면 뒤쪽 쉼이 더 가까울 수 있음 | 시작은 앞쪽, 끝은 뒤쪽 쉼으로 |
| 요약을 담은 마커가 "판 2" 라고 우김 | `load` 가 파일의 판 번호를 그대로 들고 있음 | `save()` 가 `SCHEMA_VERSION` 을 다시 찍는다 |
| 본문이 "느에미아" 로 화면에 박힘 | 글자째로 견주면 "느헤미야" 와 반도 안 닮음 | **자모로 풀어** 견준다(`export.fix_book`). '헤'와 '에'는 초성 하나 차이 |
| **임베딩이 상투구만 뽑음** | 평균 방향 코사인을 씀. 문장 벡터가 쏠려 있어 값이 0.85~0.94 에 몰린다 | 제1주성분을 걷어낸 뒤 서로간 유사도로 잰다 (`embed.importance`) |
| **맺음말·권면이 0초** | 마지막 대목 구획이 설교 끝까지 뻗어 뒤 구획을 삼킴 | 구획이 겹치지 않게 자른다. 실측 균등도 0.63 → 0.95 |
| **요약 자막이 깜빡임** | 컷을 쉼에 맞추며 벌린 여백에 이웃 문장 꼬리가 걸려 0.2초짜리 자막이 생김 | `build_srt` 에 `min_cue` 1.0초 · `min_share` 0.3 을 둔다. 실측 22줄 → 0줄 |
| 요약이 뚝뚝 끊김 | `fit_to_target` 이 문장을 빼다 조각을 둘로 쪼갬 (2초짜리 토막) | `drop_slivers` 로 4.5초 미만 조각을 뺀다. 대목 선언은 남긴다 |
| **AI 고르기가 멈춘 듯** | Qwen3 가 `<think>` 를 길게 쓰고, 응답을 통째로 기다림 | `/no_think` + `enable_thinking:false`, 흘려받으며 5초마다 진행 표시 |
| 본문 안내가 요약에 들어감 | "…5절부터 11절까지 말씀입니다" 가 되풀이 낱말로 점수를 얻음 | `_ANNOUNCE` 로 걸러 낸다 |
| 결과 파일을 덮어쓸 때 실패 | 지운 뒤 옮기면 재생기가 열어 둔 파일을 못 지움 | 같은 폴더에 임시 이름으로 두고 `os.replace` 로 갈아 끼운다 |

**문자열 치환으로 코드를 고칠 때는 치환이 실제로 됐는지 확인할 것.**
앵커가 안 맞으면 조용히 아무 일도 일어나지 않는다. 실제로 `ZoomBar` 클래스가
통째로 누락된 채 넘어간 적이 있다.

**빌드가 계속 IndexError 로 죽으면 패키지를 의심하기 전에 파이썬 버전을 볼 것.**
`--collect-all` 대상을 바꿔 가며 반나절을 썼지만 원인은 인터프리터였다.
PyInstaller 로그 5번째 줄에 `Python: 3.10.0rc1` 이 찍혀 있었다.

## 6. 빌드와 배포

```powershell
pip install pyinstaller
build_all.bat            # lite
build_all.bat full       # torch 포함 (권장하지 않음)
```

`dist\SermonTool\` 약 805MB. 구성:

| | 크기 |
|---|---|
| ffmpeg + ffprobe | 278MB |
| PySide6 | ~150MB |
| yt-dlp + deno | 115MB |
| faster-whisper + ctranslate2 + onnxruntime (자막) | ~190MB |
| sherpa-onnx (성문) | ~30MB |
| campplus.onnx (성문 모델) | 28MB |
| voiceprint.npz (목사님 성문) | 2KB |

자막 기능이 필요 없으면 `LITE_COLLECT_*` 에서 faster-whisper 계열을 빼면
약 200MB 줄어든다.

### 배포

기본은 **`dist\SermonTool` 폴더를 압축해 전달**한다. 받는 쪽은 압축을 풀고
안의 `SermonTool.exe` 를 실행하면 끝이다. 설치본(Inno Setup)은 바로가기와
제어판 제거 항목이 필요할 때만 만든다.

### 프리즈 환경 대응

- `util.PROJECT_ROOT` 가 `sys._MEIPASS` 를 본다
- 데이터는 `%LOCALAPPDATA%\SermonTool\data\` 에 쓴다 (Program Files 는 쓰기 불가)
- 성문은 사용자 폴더 우선, 없으면 exe 에 묶인 기본 성문

### 32비트 Windows

지원하지 않는다. **PySide6(Qt6)가 32비트 Windows 휠을 내지 않는다.**
Qt 6 부터 32비트 Windows 지원을 뺐다. deno 도 32비트 빌드가 없고,
FFmpeg 공식 빌드도 64비트만 나온다.

꼭 필요하면 GUI 를 Qt5(PySide2)로 다시 짜야 하는데, QMediaPlayer API 가
Qt6 와 크게 달라 프리뷰 부분을 새로 만들어야 한다. 두 벌을 관리하는 비용도 든다.
Windows 10 32비트는 2025년 10월에 지원이 끝났으므로, 그 PC 에서는
결과물 재생만 하고 편집은 64비트 PC 에서 하는 편이 현실적이다.

### 절대 하지 말 것

- `--collect-all` 로 `yt_dlp`, `PySide6` 를 묶기 → modulegraph 가 죽는다
- torch 계열을 lite 빌드에 넣기 → 3~6GB
- `bin/` 을 비운 채 배포 → 사용자가 FFmpeg 를 직접 깔아야 한다

## 8. GUI 설계 원칙

컴퓨터에 익숙하지 않은 분들이 쓴다는 전제로 만들었다.

- **단축키 없이 마우스만으로** 모든 작업이 된다. 단축키는 덤이다.
- 버튼 글자가 **무슨 일이 일어나는지** 그대로 말한다 (`여기가 시작`, `이 지점 확인`).
- 화면 아래 안내줄이 **지금 할 일**을 계속 알려 준다.
- 로그는 작업마다 굵은 선으로 갈리고, 끝날 때 `→ 다음:` 으로 다음 행동을 알려 준다.
- 못 쓰는 기능은 비활성화하고 **툴팁에 이유**를 적는다 (`_startup_check`).
- 실수를 되돌릴 수 있다 — `Ctrl+Z`, `[AI가 찾은 구간으로]`.
- 화면 색은 OS 테마와 무관하게 고정한다. PC 마다 달라 보이면 설명서와 어긋난다.
- 창 크기는 모니터에 맞춰 정하고, 세로가 좁으면 편집 패널을 한 단계 더 줄인다
  (`_fit_to_screen`, `_compact_for_small_screen`).

파일 이름은 사람이 적은 **설교 제목**으로 만든다 (`export.safe_stem`).
윈도우에서 못 쓰는 문자는 걸러 내고, 비어 있으면 날짜와 영상 id 로 대체한다.

## 9. 아직 안 한 것

> 우선순위와 배경은 `docs/HANDOVER.md` 7장에 정리되어 있다. 여기서는 기술적 메모만 남긴다.


- **라이브 실시간 검출** — 방송 중 3초씩 판정해 설교 시작·끝을 표시.
  성문 방식이라 CPU 로 충분히 가능하다(실시간의 100배 여유).
  스트림 녹화·재접속 처리가 남아 있다.
- **자막 위치·크기 GUI 조절** — 지금은 `cfg.subtitle_font` / `subtitle_size` 로만
  바꿀 수 있고 화면에는 노출하지 않았다.
- **임베딩·AI 모델의 실제 품질 확인** — 배관은 가짜 모델·가짜 서버로 검증했지만
  진짜 모델로 견주는 것은 아직이다. `python setup_ai.py` 로 이 PC 에서 해야 한다.
- **다른 설교의 구조 확인** — 3분 요약의 뼈대는 목사님이 "첫 번째에요" 처럼 번호로
  선언하시는 것에 기댄다. 영상 한 편으로만 확인했다. 3~4편이 더 필요하다.
- **세로 크롭 구도 재확인** — 영상 한 편으로 맞춘 비율이다. 고정 카메라라 매주
  같겠지만 다음 영상에서 한 번 보는 것이 좋다.
- **요약 목표 길이 GUI 조절** — 지금은 `cfg.summary_target` (180초) 로만 바꾼다.
  "너무 잘게 끊긴다" 는 말이 나오면 5분 선택지를 화면에 내면 된다.
- **완료 알림** — 지금은 로그 파일을 봐야 안다.
- **배치 탭** — 폴더 일괄 분석.
- **학습 모델** — 라벨이 30~50편 쌓인 뒤에나 의미가 있다.
  `detect.py` 인터페이스를 고정해 두었으므로 그 파일만 교체하면 된다.
