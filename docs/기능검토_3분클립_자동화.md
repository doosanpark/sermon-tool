# 기능 검토 — 설교 영상에서 3분 클립 자동으로 뽑기

> **주의**: 이 문서는 "한 대목을 연속으로 3분 잘라내기" 전제로 쓴 것입니다.
> 실제 목표는 "핵심만 골라 3분으로 압축"이므로 `기능검토_설교3분요약.md` 를 보세요.
> 아래 내용 중 쉼 분석·`marker.clips` 충돌·API 키·화면 비율 부분은 그대로 유효합니다.

- 검토일: 2026-08-31 (코드 작성 전 가능성 검토)
- 정한 방식: **AI가 전사문을 읽고 후보 선정 → 사람이 듣고 확정**
- 실측 근거: `data/audio/ZEKoljLiXOw.wav`, `data/cache/ZEKoljLiXOw.transcript.json`, `data/preview/ZEKoljLiXOw.mp4`

## 결론

**됩니다.** 자를 자리는 넉넉하고 편집기 구조도 받아들일 준비가 돼 있습니다.
다만 세 가지를 미리 알고 시작해야 합니다.

1. **전사문만 보고는 자를 자리를 못 찾습니다.** 오디오를 한 번 더 훑는 단계가 반드시 필요합니다.
2. **후보를 `marker.clips` 에 넣으면 안 됩니다.** 설교 영상 내보내기가 망가집니다.
3. **가장 어려운 건 클립 고르기가 아니라 API 키를 사용자에게 받는 일입니다.**

| 항목 | 판정 |
|---|---|
| 깔끔한 3분 구간이 실제로 존재하는가 | **확인됨** — 문단급 쉼 87곳, 3분 창 후보 82개 중 73개 양끝 정렬 가능 |
| 전사문만으로 컷 지점을 정할 수 있는가 | **불가** — 문장 간격이 전부 0.000초 |
| 쉼 찾기를 새 의존성 없이 붙일 수 있는가 | **가능** — numpy + wave 로 몇 초 |
| 후보를 편집기 목록에 넣기 | **주의** — 별도 필드 필요, `schema_version` 3 |
| 세로(9:16) 숏폼 | **권고 있음** — 크롭하면 설교 제목 화면이 날아감 |
| AI 호출 규모·비용 | **문제 없음** — 1~1.6만 토큰, 영상 1편당 1회 |
| API 키 받기 | **가장 어려움** — 지금 바깥 API를 하나도 안 씀 |

## 1. 자를 자리는 넉넉합니다 (실측)

설교 구간 오디오를 50ms 프레임 RMS 로 훑어 실제 무음을 찾았습니다.
배경소음 바닥 −68.5dB → 판정선 −60.5dB.

```
설교 36.2분 (1935.0 ~ 4110.0s), 프레임 43,500개

  0.3초 이상 쉼 : 528곳
  0.5초 이상 쉼 : 433곳
  0.8초 이상 쉼 : 300곳   ← 평균 7초에 한 번 (호흡급)
  1.2초 이상 쉼 : 197곳
  2.0초 이상 쉼 :  87곳   ← 평균 25초에 한 번 (문단급)

문단급 쉼에서 시작하는 3분 창:
  시작 후보 82개 중 73개(89%)가 3분±30초 안에 문단급 끝을 가짐
  목표 180초에서 벗어난 정도 중앙값 7초
```

**→ 양끝이 모두 목사님이 숨을 고르시는 자리에 놓이는 3분 클립을 만들 수 있습니다.**

## 2. ★ 전사문에는 쉼 정보가 없습니다

가장 중요한 발견입니다.

```
설교 문장 550개 사이 간격
  +0.000s : 550건    ← 전부
  양수(무음) 0건 / 음수(겹침) 0건
```

`faster-whisper` 를 `vad_filter=True` 로 돌리기 때문에 무음이 잘려 나가고 말만 이어 붙습니다
(`core/transcribe.py`). 그래서 전사문에는 끊긴 자리가 하나도 없습니다.

```
문장 시작점 → 가장 가까운 실제 쉼까지 거리
  중앙값 1.98초 · 90%가 8.58초 이내 · 최대 49.03초
```

**AI 가 "이 문장부터"라고 골라도 그대로 자르면 말 중간에서 시작할 수 있습니다.**

### 해법 — 스냅 단계

AI 가 고른 문장 번호를 받아 **근처의 진짜 쉼으로 끌어다 붙입니다.**

- 새로 받을 것 없음: numpy + 표준 `wave` 만으로 됨 (이번 측정이 그 방법)
- 더 정확히 하려면 `bin/models/silero_vad.onnx` 가 이미 번들돼 있음
- wav 는 이미 `data/audio/` 에 있음
- 36분 구간 훑는 데 몇 초. CUDA·torch 불필요 → `CLAUDE.md` 제약 통과

## 3. ★ `marker.clips` 에 후보를 넣으면 안 됩니다

```
core/marker.py  ranges()
    clips 가 비어 있지 않으면 clips 를 그대로 돌려준다

core/export.py:111
    picked = [(s, e) for s, e, label in marker.ranges() if label != "benediction"]
```

후보 5개를 `clips` 에 넣으면 **[3. 설교 영상 만들기] 가 후보 5개를 이어붙인 15분 영상을 뱉습니다.**
사용자는 원인을 알 방법이 없습니다.

**해법**: 후보는 `Marker` 에 별도 필드(예: `clip_candidates`)로 두고, 사람이 고른 하나만 클립 내보내기로 넘김.
`schema_version` 을 3 으로 올리고, 옛 마커를 읽을 때 없는 필드는 빈 목록으로.
(`Marker.from_dict` 가 모르는 키를 버리게 돼 있어 반대 방향은 이미 안전합니다.)

## 4. 순서 — 전사가 먼저

전사는 "확정된 구간에만" 돕니다 (`app.py` 가 `marker.ranges()` 를 돌며 호출).
2시간 영상 전체를 전사하지 않으려는 의도적 구조이고 그대로 두는 게 맞습니다.

```
[자동으로 찾기] → 설교 구간 확정 → 전사 → 그 다음에야 클립 후보
```

**사용자가 자막 만들기를 건너뛰면 클립 버튼이 아무것도 못 합니다.**
버튼을 흐리게 두고 "설교 구간을 찾은 뒤 눌러 주세요" 처럼 **무엇을 누르면 되는지**를 적어야 합니다.

## 5. 화면 비율 — 원본을 열어 확인

`ffprobe` + 프레임 2장(50분·75분) 확인 결과:

- **1280×720, 30fps, h264, 고정 카메라 한 대**
- 두 프레임의 구도가 거의 동일 → **자를 좌표를 한 번만 정하면 모든 영상에 재사용.**
  얼굴 추적 불필요 → 자동화에 매우 유리
- 목사님은 화면 가로 **40~45% 지점**
- **오른쪽 절반이 설교 제목 화면** ("기도로 구조를 다시 세우다")
- 왼쪽에 십자가, 오른쪽 위에 교회 로고, 아래쪽에 회중

**9:16 크롭 시 문제**: 720 높이 기준 폭 **405px** 만 남음 → 제목 화면과 십자가가 통째로 잘림.
405px 를 세로 1080 으로 늘리면 화질도 떨어짐.

**권고**: 세로가 필요하면 크롭보다 **원본을 세로 캔버스 가운데 얹고 위에 설교 제목, 아래에 자막**.
정보 손실 없음, 구현도 단순, 화질 손실 없음. 가로 그대로 쓰면 이 고민 자체가 없음.

## 6. AI 호출 — 규모는 문제 없음

- 설교 전사문 14,304자 ≈ 1~1.6만 토큰 → 한 번에 들어감
- 영상 1편당 호출 1회. 주일예배 기준 연 52회
- 비용은 사실상 무시할 수준

## 7. ★ 진짜 걸림돌 — API 키

**이 프로그램은 지금 바깥 API 를 하나도 쓰지 않습니다.**
네트워크는 `bin/yt-dlp.exe` 실행이 전부이고, 코드에서 `requests` 조차 쓰지 않습니다.

이미 한 번 겪은 자리가 있습니다 — `core/config.py` 의 `read_hf_token()` 주석:

> "setx 는 새 터미널부터 적용되기 때문에 매번 걸리기 쉽다.
>  프로젝트 폴더에 .hf_token 파일 하나만 만들어 두면 그 문제를 겪지 않는다."

토큰 받기가 어렵다는 걸 이미 겪고 파일로 우회한 흔적입니다. 게다가 그 토큰은 화자 분리용이라
지금은 기본 경로에서 밀려나 있습니다.

여기에 `CLAUDE.md` 가 겹칩니다 — **"컴퓨터에 익숙하지 않은 분들이 이 프로그램을 씁니다."**

필요한 건 클립 고르기 로직이 아니라 그 주변입니다:
설정 화면의 키 입력란, 키 없을 때의 표시, 인터넷 끊겼을 때의 문구, 키 저장 위치.
**이쪽이 일이 더 많습니다.**

## 8. 자막을 태우려면 오인식 정리가 먼저

숏폼은 소리를 끄고 보는 분이 많아 자막을 태우는 쪽이 보통 낫습니다.
다만 태우면 오인식이 화면에 박히고 되돌릴 수 없습니다.

```
느에미아 / 니에미아  → 느헤미야
가난인의 사랑        → 하나님의 사랑
성경의 교통하심      → 성령의 교통하심
```

`논문검토_NexusSum_DIAMOND_적용가능성.md` 에서 권한 **치환 사전**이 여기서 선행 조건이 됩니다.

## 9. 권하는 만드는 순서

앞의 셋은 인터넷도 키도 없이 됩니다. **셋만 있어도 클립 기능은 돌아갑니다.**

1. **쉼 찾기 모듈** (키 불필요)
   어떤 방식으로 고르든 반드시 거쳐야 하는 단계라 먼저 만들어 두는 게 이득.
2. **후보 필드 + 편집기 목록** (키 불필요)
   `marker.clips` 와 섞이지 않는 별도 필드. 미리 듣고 고르는 화면까지.
   이때 후보는 규칙으로 만들어도 됨 — "문단급 쉼에서 시작하는 3분 창" 정도면 충분.
3. **클립 내보내기** (키 불필요)
   `core/cut.py` 에 자르기·음량·자막이 이미 다 있음. 새로 만드는 건 화면 비율 처리 정도.
   **여기까지가 완성된 기능.**
4. **AI 선정 + 키 설정 화면** (키 필요)
   후보 생성 부분만 갈아 끼움. 꺼져도 프로그램은 그대로 돌아감.

### 이 순서를 권하는 이유

AI 선정을 먼저 만들면 키를 안 넣은 사람에게는 **기능이 통째로 없는 것**이 됩니다.
반대로 쉼 찾기와 후보 화면을 먼저 세우면 키가 없어도 클립을 뽑을 수 있고, AI 는 그 위에 얹히는 개선이 됩니다.

지금 성문 검출이 그 모양입니다 — 성문이 없으면 화자 분리로 떨어지고, 있으면 60배 빨라집니다.
**기능이 사라지는 게 아니라 느려질 뿐입니다.** 클립도 같은 모양으로.
