# 예배영상 설교구간 자동추출 개발명세서

작성일 2026.8.25(화)

목적: 기독교 예배 영상에서 설교 구간을 AI로 제안하고 사람이 30초 확인한 뒤 영상과 SRT로 내보내는 반복 작업 자동화.

## 1. 목표

기독교 예배 영상(1~2시간)에서 설교 구간만 자동 추출해 별도 영상으로 내보낸다. 주 1회 반복 작업이며, 완전 자동이 아니라 "AI 제안 → 사람 30초 확인 → 내보내기" 구조를 전제로 한다. 부가 산출물로 설교 구간 자막(SRT)을 함께 생성한다.

## 2. 도메인 전제 (설계 근거)

예배 순서와 화자 구조가 고정적이라는 전제를 사용한다.

| 순서 | 화자 | 길이 | 비고 |
| --- | --- | --- | --- |
| 찬양 | 인도자 또는 음악 | 가변 | 화자분리 혼선 구간 |
| 대표기도 | 화자 B | 3~5분 | 목사와 다른 사람 |
| 성경봉독 | 화자 C (목사) | 1~2분 | 설교와 동일 화자 |
| 설교 | 화자 C (목사) | 30~40분 | 추출 대상 |
| 축도 | 화자 C (목사) | 1~2분 | 영상 끝, 앞에 긴 공백 |

> **핵심 관찰:** 설교는 단일 화자가 가장 오래 연속 발화하는 유일한 구간이다. 봉독과 설교는 사실상 붙어 있고, 축도는 앞에 긴 공백(찬양/헌금)을 두고 영상 끝에 위치하므로 "최장 연속 블록" 규칙만으로 자동 배제된다.

## 3. 파이프라인

1. ffmpeg로 16kHz 모노 wav 추출
2. pyannote 화자 분리 → `[(start, end, speaker)]` 리스트
3. 화자별 총 발화시간 집계 → 최다 화자 = 목사
4. 목사 구간을 `gap_threshold`(기본 90초) 기준으로 블록 병합
5. 최장 블록 = 봉독+설교 구간 확정
6. 확정 구간에만 Whisper STT 적용 (전체가 아님)
7. 자막 기반 경계 미세보정
8. 신뢰도 산출 후 JSON 저장
9. 검수 GUI에서 사람 확인
10. ffmpeg 무재인코딩 컷 + SRT 출력

> **중요:** 6번에서 전체 2시간이 아니라 확정된 37분 구간만 STT를 돌리므로 처리 시간이 약 1/3로 줄어든다. 순서를 바꾸면 안 된다.

## 4. STT의 역할 (범위 명확화)

STT는 구간 검출 자체에는 불필요하나, 제품 전체로 보면 필요하다.

| 용도 | STT 필요 여부와 이유 |
| --- | --- |
| 설교 구간 1차 검출 | 불필요. 화자 분리만으로 가능 |
| 봉독/설교 경계 분리 | 필요. 같은 화자라 음성 특징만으로는 구분 불가 |
| 경계 정밀 보정 | 필요. 초 단위 정확도 확보 |
| 자막(SRT) 삽입 | 필수. 최종 산출물 |
| 검수 효율 | 사실상 필수. 자막 없으면 확인에 2~3분, 있으면 30초 |
| 설교 제목/본문 메타데이터 추출 | 필요 |
| 향후 쇼츠 추출 | 필요 |

경계 보정 패턴 예시

- 시작 후보: "본문 말씀은", "오늘 본문", 정규식 `\d+장\s*\d+절`
- 종료 후보: "기도하겠습니다", "아멘", 직후 음악 구간 시작

## 5. 모듈 구성

```
sermon-tool/
├── analyze.py          진입점 (단일/배치)
└── core/
    ├── marker.py       마커 모델 + JSON I/O    약 30줄
    ├── diarize.py      오디오 추출 + pyannote  약 50줄
    ├── detect.py       설교 판정 + 신뢰도      약 80줄
    ├── transcribe.py   faster-whisper 래퍼     약 50줄
    ├── refine.py       자막 기반 경계 보정     약 60줄
    └── export.py       ffmpeg 컷 + SRT 출력    약 50줄
```

의존성: `pyannote.audio>=3.1`, `torch`, `torchaudio`, `faster-whisper`, 그리고 FFmpeg(별도 설치 후 PATH 등록).

pyannote 모델은 HuggingFace 토큰이 필요하다(무료, 모델 페이지에서 라이선스 동의 후 발급). Whisper 모델은 한국어 정확도를 고려해 `large-v3`를 권장하며, GPU가 없으면 `medium`을 사용한다.

## 6. 데이터 포맷

AI 예측과 사람 수정본을 모두 남긴다. 이 데이터는 그대로 향후 학습 데이터셋이 된다.

```json
{
  "video": "2026-01-05.mp4",
  "ai_start": 1938.0,
  "ai_end": 4184.0,
  "confidence": 0.95,
  "reasons": ["최장블록/2위 = 8.3배", "길이 37분 정상범위"],
  "human_start": 1935.5,
  "human_end": 4184.0,
  "corrected": true,
  "created_at": "2026-01-05T14:22:31"
}
```

**규칙:** 내보내기는 `human_*` 값이 있으면 그것을, 없으면 `ai_*` 값을 사용한다. 이 포맷은 프로젝트 초기에 확정해야 하며, 나중에 추가하려면 과거 데이터를 못 쓴다.

**신뢰도 산출 기준**

- 최장 블록과 2위 블록의 길이 비 (클수록 확실)
- 설교 길이가 25~50분 범위에 드는지
- 최다 화자의 전체 발화 점유율

## 7. 개발 순서

| 단계 | 산출물 | 완료 기준 |
| --- | --- | --- |
| 1 | `marker.py` | JSON 왕복 저장/로드 동작 |
| 2 | `diarize.py` | 화자 구간 리스트 정상 출력 |
| 3 | `detect.py` | CLI로 타임코드 출력. STT 없이 여기까지 먼저 |
| 3.5 | 정확도 측정 | 실제 영상 5편으로 검증. 90% 미만이면 알고리즘 재검토 |
| 4 | `transcribe.py` + `refine.py` | 경계 보정 적용 |
| 5 | `export.py` | mp4 + srt 산출. 여기까지가 MVP |
| 6 | `app.py` (PySide6) | 프리뷰 + 마커 수정 GUI |
| 7 | 배치 탭 | 폴더 일괄 분석 + 신뢰도 목록 |

> **강조:** 3단계를 STT 없이 먼저 진행하는 이유는 화자 분리만으로 몇 퍼센트가 나오는지 측정해야 STT에 얼마나 투자할지 판단할 수 있기 때문이다. 처음부터 전부 넣으면 각 요소의 기여도를 알 수 없다. 5단계까지면 CLI만으로 실사용 가능하며 GUI는 편의 기능이다.

## 8. GUI 사양

> **핵심 원칙:** 라벨링 툴과 편집 툴을 분리하지 않는다. 동일 화면에서 저장하면 라벨이 되고, 내보내기를 누르면 편집이 된다. 두 작업의 차이는 버튼 하나뿐이다.

```
┌────────────────────────┬──────────────┐
│                        │ [영상 열기]  │
│         영상 프리뷰    │ [AI 분석]    │
│                        │              │
├────────────────────────┤ 시작 32:18 I │
│ ▶ ────●────── 00:32:18 │ 끝 69:44 O   │
├────────────────────────┤ 신뢰도 0.95  │
│ ░░▓███████████▒░░      │              │
│  ↑AI 추정 구간         │ [저장]       │
├────────────────────────┤ [내보내기]   │
│ 자막 패널 (클릭시 이동)│              │
└────────────────────────┴──────────────┘
```

단축키: I=시작 마커, O=끝 마커, Space=재생/정지, J/K/L=셔틀. 버튼과 단축키는 QAction으로 통합 정의해 이중 관리를 피한다.

자막 패널은 검수 효율의 핵심이다. 텍스트를 훑어 경계를 찾고 클릭하면 해당 시각으로 이동하는 방식으로 구현한다.

## 9. 학습 모델 도입 시점

현 시점에 딥러닝 학습은 권장하지 않는다.

- 라벨 데이터가 0편이다
- 규칙 방식 결과로 자동 라벨링하면 90%짜리 라벨로 90%짜리 모델을 얻어 이득이 없다 (스승보다 나은 제자는 나오지 않음)
- 규칙 방식 예상 정확도 90% 이상, 개발 1~2일. 학습 방식은 1~2주
- 주 1회 작업이므로 잔여 오차는 사람이 30초 확인으로 메운다

도입 시점: 6~12개월 운영 후 라벨 30~50편이 축적된 시점. 이때 라벨은 사람이 검증한 것이므로 품질이 100%에 가깝다.

도입 시 방식: 영상 프레임 직접 학습이 아니라 초당 특징벡터 기반 이진 분류.

- 특징: `[화자 onehot, RMS, 음악여부, 장면전환율, 영상내 상대위치]`
- 모델: LightGBM 이진 분류 (GPU 불필요)
- 후처리: 연속구간 병합, 짧은 구멍 메우기

설계 요구사항: `detect.py`만 교체하면 되도록 입출력 인터페이스를 고정해 둔다.

## 10. 리스크와 대응

| 리스크 | 대응 |
| --- | --- |
| 찬양 구간에서 화자 분리 혼선 | 음악 구간을 사전 마스킹 후 분리 |
| 봉독/설교 경계 모호 | 기본은 봉독 포함. 분리 필요 시 Whisper 구절 인용 패턴 검출 |
| 교회별 예배 순서 차이 | gap_threshold를 파라미터화 |
| 2시간 영상 처리 시간 | 오디오만 추출, 앞 20분/뒤 10분 트림 옵션 제공 |
| Whisper 처리 시간 | 확정 구간에만 적용 (전체 대비 약 1/3) |
| 축도가 설교로 오인 | 최장 블록 규칙으로 자동 배제. 길이 검증 추가 |

## 11. 사전 확인 사항

**개발 착수 전 반드시 확인할 것:** 대상 영상이 유튜브 업로드본이라면 `yt-dlp --write-info-json`으로 챕터 정보 유무를 먼저 확인한다. 설교 시작 시각이 챕터로 이미 기록되어 있다면 위 파이프라인 전체가 불필요하다.

추가 확인 사항

- 설교 시작 화면에 고정 자막/타이틀이 뜨는가 (뜬다면 OCR 한 번으로 해결 가능)
- 매주 카메라 구도와 예배 순서가 동일한가
