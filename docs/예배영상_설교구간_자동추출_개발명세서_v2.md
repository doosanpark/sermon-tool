# 예배영상 설교구간 자동추출 개발명세서 v2

개정일 2026.8.25(화) · v1 대비 변경: 유튜브 소스 확정, yt-dlp 연동 추가, 챕터 분기 제거

## 0. v1 대비 변경 요약

| 항목 | v1 | v2 |
|---|---|---|
| 입력 소스 | 로컬 mp4 파일 | 유튜브 URL |
| 챕터 활용 | 사전 확인 후 지름길 가능 | **확인 결과 챕터 없음. 분기 제거** |
| 다운로드 | 해당 없음 | 분석은 오디오만, 내보내기는 구간 부분 다운로드 |
| 신규 모듈 | - | fetch.py (yt-dlp 래퍼) |
| STT 위치 | 구간 검출에 불필요 | 검출에는 불필요하나 경계보정·자막·검수에 필요 |

> 대상 채널 확인 결과 챕터 정보가 없고 예배 전체가 단일 영상으로 업로드된다. 따라서 화자 분리 기반 자동 검출이 유일한 경로다.

## 1. 목표

유튜브에 업로드된 예배 영상(1~2시간)에서 설교 구간만 자동 검출해 별도 영상과 자막(SRT)으로 내보낸다. 주 1회 반복 작업이며 완전 자동이 아니라 "AI 제안 → 사람 30초 확인 → 내보내기" 구조를 전제로 한다.

## 2. 도메인 전제 (설계 근거)

예배 순서와 화자 구조가 고정적이라는 전제를 사용한다.

| 순서 | 화자 | 길이 | 비고 |
|---|---|---|---|
| 찬양 | 인도자 또는 음악 | 가변 | 화자분리 혼선 구간 |
| 대표기도 | 화자 B | 3~5분 | 목사와 다른 사람 |
| 성경봉독 | 화자 C (목사) | 1~2분 | 설교와 동일 화자 |
| 설교 | 화자 C (목사) | 30~40분 | 추출 대상 |
| 축도 | 화자 C (목사) | 1~2분 | 영상 끝, 앞에 긴 공백 |

> 핵심 관찰: 설교는 단일 화자가 가장 오래 연속 발화하는 유일한 구간이다. 봉독과 설교는 사실상 붙어 있고, 축도는 앞에 긴 공백(찬양/헌금)을 두고 영상 끝에 위치하므로 "최장 연속 블록" 규칙만으로 자동 배제된다.

## 3. 파이프라인

1. yt-dlp로 채널 신규 영상 감지
2. **오디오만** 다운로드 (16kHz 모노 wav)
3. pyannote 화자 분리 → `[(start, end, speaker)]`
4. 화자별 총 발화시간 집계 → 최다 화자 = 목사
5. 목사 구간을 `gap_threshold`(기본 90초) 기준으로 블록 병합
6. 최장 블록 = 봉독+설교 구간 확정
7. 확정 구간에만 Whisper STT 적용
8. 자막 기반 경계 미세보정
9. 신뢰도 산출 후 JSON 저장
10. 검수 GUI에서 사람 확인
11. 확정 구간만 영상 부분 다운로드
12. ffmpeg 무재인코딩 컷 + SRT 출력

> 중요: 2단계에서 오디오만 받으면 2~3GB가 수십 MB로 줄고, 11단계에서 확정 구간만 받으면 2시간이 아닌 37분치만 다운로드한다. 7단계에서 전체가 아닌 확정 구간에만 STT를 돌리므로 처리 시간이 약 1/3로 줄어든다. 순서를 바꾸면 안 된다.

## 4. 다운로드 전략

분석과 내보내기를 분리한다.

```bash
# 1차: 분석용 오디오만 (수십 MB)
yt-dlp -f bestaudio -x --audio-format wav \
       --postprocessor-args "-ac 1 -ar 16000" \
       -o "%(upload_date)s_%(id)s.wav" URL

# 2차: 타임코드 확정 후 해당 구간만
yt-dlp --download-sections "*00:32:18-01:09:44" \
       --force-keyframes-at-cuts -f "bv*+ba/best" URL
```

주의사항
- 본인 교회 채널 등 다운로드 권한이 있는 영상만 사용한다
- yt-dlp는 유튜브 변경에 따라 자주 깨진다. `pip install -U yt-dlp` 정기 실행과 실패 시 재시도·명확한 에러 메시지를 구현한다

## 5. STT의 역할 (범위 명확화)

STT는 구간 검출 자체에는 불필요하나 제품 전체로 보면 필요하다.

| 용도 | STT 필요 여부와 이유 |
|---|---|
| 설교 구간 1차 검출 | 불필요. 화자 분리만으로 가능 |
| 봉독/설교 경계 분리 | 필요. 같은 화자라 음성 특징만으로는 구분 불가 |
| 경계 정밀 보정 | 필요. 초 단위 정확도 확보 |
| 자막(SRT) 삽입 | 필수. 최종 산출물 |
| 검수 효율 | 사실상 필수. 자막 없으면 확인에 2~3분, 있으면 30초 |
| 설교 제목/본문 메타데이터 추출 | 필요 |
| 향후 쇼츠 추출 | 필요 |

경계 보정 패턴 예시
- 시작 후보: "본문 말씀은", "오늘 본문", 정규식 `\d+장\s*\d+절`
- 종료 후보: "기도하겠습니다", "아멘", 직후 음악 구간 시작

## 6. 모듈 구성

```
sermon-tool/
├── analyze.py          진입점 (단일/배치)
└── core/
    ├── fetch.py        yt-dlp 래퍼           약 60줄
    ├── marker.py       마커 모델 + JSON I/O  약 30줄
    ├── diarize.py      오디오 + pyannote     약 50줄
    ├── detect.py       설교 판정 + 신뢰도    약 80줄
    ├── transcribe.py   faster-whisper 래퍼   약 50줄
    ├── refine.py       자막 기반 경계 보정   약 60줄
    └── export.py       ffmpeg 컷 + SRT       약 50줄
```

의존성: `yt-dlp`, `pyannote.audio>=3.1`, `torch`, `torchaudio`, `faster-whisper`, FFmpeg(별도 설치 후 PATH 등록).

pyannote 모델은 HuggingFace 토큰이 필요하다(무료, 모델 페이지에서 라이선스 동의 후 발급). Whisper 모델은 한국어 정확도를 고려해 `large-v3`를 권장하며 GPU가 없으면 `medium`을 사용한다.

## 7. 신뢰도 산출

챕터가 없으므로 자동 판정 결과가 유일한 근거다. 신뢰도 산출이 v1보다 중요해졌다.

```python
def confidence(blocks, pastor_ratio):
    top, second = blocks[0], blocks[1]
    ratio = top.duration / max(second.duration, 1)

    score = 0.0
    score += 0.4 if ratio > 5 else 0.4 * (ratio / 5)       # 최장/2위 비율
    score += 0.4 if 25*60 <= top.duration <= 50*60 else 0  # 길이 정상범위
    score += 0.2 * min(pastor_ratio / 0.5, 1.0)            # 목사 발화 점유율
    return round(score, 2)
```

운용 기준
- 0.9 이상: 자동 통과
- 0.7~0.9: 자막 훑어보고 확인
- 0.7 미만: 영상 프리뷰로 직접 확인

## 8. 데이터 포맷

AI 예측과 사람 수정본을 모두 남긴다. 이것이 곧 학습 데이터셋이 된다.

```json
{
  "video_id": "dQw4w9WgXcQ",
  "upload_date": "20260824",
  "ai_start": 1938.0,
  "ai_end": 4184.0,
  "confidence": 0.95,
  "reasons": ["최장블록/2위 = 8.3배", "길이 37분 정상범위"],
  "human_start": 1935.5,
  "human_end": 4184.0,
  "corrected": true,
  "created_at": "2026-08-24T14:22:31"
}
```

내보내기는 `human_*`이 있으면 그 값을, 없으면 `ai_*`를 사용한다.

> 이 포맷은 초기에 확정해야 한다. 나중에 `human_*` 필드를 추가하면 그전에 쌓인 데이터는 학습에 쓸 수 없다.

## 9. 개발 순서

| 단계 | 산출물 | 완료 기준 |
|---|---|---|
| 0 | 전제 검증 스크립트 | **영상 1편으로 목사가 최다 화자로 잡히는지 확인** |
| 1 | fetch.py | 채널 목록 조회 + 오디오 다운로드 동작 |
| 2 | marker.py | JSON 왕복 저장/로드 동작 |
| 3 | diarize.py | 화자 구간 리스트 정상 출력 |
| 4 | detect.py | CLI로 타임코드 출력. STT 없이 여기까지 먼저 |
| 4.5 | 정확도 측정 | 실제 영상 5편으로 검증. 90% 미만이면 알고리즘 재검토 |
| 5 | transcribe.py + refine.py | 경계 보정 적용 |
| 6 | export.py | mp4 + srt 산출. 여기까지가 MVP |
| 7 | app.py (PySide6) | 프리뷰 + 마커 수정 GUI |
| 8 | 배치 탭 | 폴더 일괄 분석 + 신뢰도 목록 |

> 0단계를 먼저 하는 이유: 목사가 최다 화자로 잡히지 않으면 설계 전제 자체가 흔들린다. 코드 작성 전에 반드시 확인한다.
>
> 4단계를 STT 없이 먼저 진행하는 이유: 화자 분리만으로 몇 퍼센트가 나오는지 측정해야 STT에 얼마나 투자할지 판단할 수 있다. 처음부터 전부 넣으면 각 요소의 기여도를 알 수 없다. 6단계까지면 CLI만으로 실사용 가능하며 GUI는 편의 기능이다.

## 10. 0단계 검증 스크립트

```python
# check_speakers.py — 설계 전제 검증용
import sys, os
from collections import defaultdict
from pyannote.audio import Pipeline
import torch

pipe = Pipeline.from_pretrained(
    "pyannote/speaker-diarization-3.1",
    use_auth_token=os.environ["HF_TOKEN"]
)
if torch.cuda.is_available():
    pipe.to(torch.device("cuda"))

diar = pipe(sys.argv[1])

total = defaultdict(float)
segs = []
for turn, _, spk in diar.itertracks(yield_label=True):
    total[spk] += turn.end - turn.start
    segs.append((turn.start, turn.end, spk))

print("=== 화자별 총 발화시간 ===")
for spk, sec in sorted(total.items(), key=lambda x: -x[1]):
    print(f"{spk}: {sec/60:.1f}분")

top_spk = max(total, key=total.get)
blocks, cur = [], None
for s, e, spk in segs:
    if spk != top_spk:
        continue
    if cur and s - cur[1] <= 90:
        cur = (cur[0], e)
    else:
        if cur: blocks.append(cur)
        cur = (s, e)
if cur: blocks.append(cur)

blocks.sort(key=lambda b: -(b[1]-b[0]))
print(f"\n=== {top_spk} 최장 블록 TOP 3 ===")
for s, e in blocks[:3]:
    print(f"{int(s//3600):02d}:{int(s%3600//60):02d}:{int(s%60):02d} ~ "
          f"{int(e//3600):02d}:{int(e%3600//60):02d}:{int(e%60):02d}  ({(e-s)/60:.1f}분)")
```

기대 출력

```
=== 화자별 총 발화시간 ===
SPEAKER_02: 41.3분   ← 목사
SPEAKER_00: 8.2분
SPEAKER_01: 4.1분

=== SPEAKER_02 최장 블록 TOP 3 ===
00:32:18 ~ 01:09:44  (37.4분)   ← 설교
01:15:20 ~ 01:16:50  (1.5분)    ← 축도
00:12:05 ~ 00:13:10  (1.1분)
```

이 결과가 실제 설교 시각과 일치하면 설계가 검증된 것이며 이후는 배관 작업이다.

## 11. GUI 사양

라벨링 툴과 편집 툴을 분리하지 않는다. 동일 화면에서 저장하면 라벨, 내보내기를 누르면 편집이다.

```
┌────────────────────────┬──────────────┐
│      영상 프리뷰        │ [URL 입력]   │
│                        │ [AI 분석]    │
├────────────────────────┤ 시작 32:18 I │
│ ▶ ──●──────  00:32:18  │ 끝  69:44 O  │
├────────────────────────┤ 신뢰도 0.95  │
│ ░░▓███████████▒░░      │ [저장]       │
│    ↑AI 추정 구간        │ [내보내기]   │
├────────────────────────┴──────────────┤
│ [00:32:18] 오늘 본문은 요한복음 3장… │ ← 자막 패널
└───────────────────────────────────────┘
```

- 단축키: I=시작, O=끝, Space=재생/정지, J/K/L=셔틀
- 버튼과 단축키는 QAction으로 통합해 이중 정의를 피한다
- 자막 패널 클릭 시 해당 시각으로 시크. 검수 시간을 2~3분에서 30초로 줄이는 핵심 기능이다

## 12. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 찬양 구간에서 화자 분리 혼선 | 음악 구간을 사전 마스킹 후 분리 |
| 봉독/설교 경계 모호 | 기본은 봉독 포함. 분리 필요 시 Whisper 구절 인용 패턴 검출 |
| 교회별 예배 순서 차이 | gap_threshold를 파라미터화 |
| 2시간 영상 처리 시간 | 오디오만 추출, 앞 20분/뒤 10분 트림 옵션 제공 |
| Whisper 처리 시간 | 확정 구간에만 적용 (전체 대비 약 1/3) |
| 축도가 설교로 오인 | 최장 블록 규칙으로 자동 배제. 길이 검증 추가 |
| yt-dlp 동작 불능 | 정기 업데이트, 실패 시 명확한 에러와 재시도 |
| 정확도 90% 미달 | 음악 구간 검출(librosa, inaSpeechSegmenter)을 보조 신호로 추가 |

보조 신호 아이디어: 설교 앞뒤에는 거의 항상 찬양이 있다. "긴 무음악 구간"을 교차검증에 사용할 수 있다.

## 13. 학습 모델 도입 시점

현 시점에 딥러닝 학습은 권장하지 않는다.

- 라벨 데이터가 0편. 규칙 방식 결과로 자동 라벨링하면 90%짜리 라벨로 90%짜리 모델을 얻어 이득이 없다
- 규칙 방식 예상 정확도 90% 이상, 개발 1~2일. 학습은 1~2주
- 주 1회 작업이므로 나머지 오차는 사람이 30초 확인으로 메운다

6~12개월 운영 후 30~50편이 쌓이면 도입한다. 그때도 영상 프레임 학습이 아니라 초당 특징벡터 기반 이진 분류로 충분하다.

```
특징: [화자 onehot, RMS, 음악여부, 장면전환율, 영상내 상대위치]
→ 1초 단위 LightGBM 이진 분류 → 연속구간 병합 후처리
```

`detect.py`만 교체하면 되도록 인터페이스를 고정해 둘 것.
